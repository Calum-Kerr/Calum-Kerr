# Calum Kerr

I build data-led web tools, and most of my time goes on [Dialegein](https://dialegein.com), an independent
index of PDF tools.

The index exists because the useful questions about a PDF tool are usually unanswered. Where are your files
processed? What does it really cost, including the tier nobody advertises? Can it remove content, or does it
only cover it up? Is the site even working today?

## Dialegein

[Dialegein](https://dialegein.com) holds 154 tools, each with a source and a date behind every field. Where
nothing has established a fact, the record says so rather than filling the gap with something plausible, and
the site publishes its own mistakes at [dialegein.com/corrections](https://dialegein.com/corrections) with the
commit that fixed each one. It is a sole trader business rather than a side project, and the data, the build
and the checks all live in one repository.

## did-it-upload

[did-it-upload](https://github.com/Calum-Kerr/did-it-upload) answers one question: when a web tool asks you to
drop a file in, does the file leave your machine? It drives the tool in a real browser with a marked file and
records every request, and it runs three controls against itself before it will report anything, because a
detector that says "no upload" is otherwise indistinguishable from a detector that is broken. MIT licensed,
free, and it stays that way.

## How I work

I would rather not publish a number I have not seen on a live page. So a fair amount of the work is reading
vendors' own documentation, recording what it does and does not establish, and writing down the difference. A
claim that turns out to be wrong gets fixed and listed, and the record of that is public, because an index
built on checkable facts cannot quietly move one.
